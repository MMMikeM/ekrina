Build the palette an editor opens on a shortcut, where you type part of a command, see the best eight and pick one.
Each of the five steps below adds one thing to it and runs on this page as it stands after that step.
Every step is written twice, as plain TypeScript and as a React component, and picking one in any tab switches every tab on the page.
Every file shown is in [`examples/command-palette`](https://github.com/MMMikeM/ekrina/tree/main/examples/command-palette), and the finished palette is `src/palette.ts`, or `src/react/palette.tsx` in React:

<Tabs syncKey="framework">
	<TabItem label="Vanilla">
		<CommandPalette step={5} />
	</TabItem>
	<TabItem label="React">
		<CommandPalette step={5} framework="react" />
	</TabItem>
</Tabs>

Some queries to try in it:

| Type        | Finds                    | Because                                          |
| ----------- | ------------------------ | ------------------------------------------------ |
| `gc`        | Git: Commit              | the title's initials, with acronyms turned on     |
| `console`   | Toggle Terminal          | a keyword the title doesn't contain              |
| `repl find` | Find and Replace         | every word of the query, in any order            |
| `termnial`  | Toggle Terminal          | a corrected typo, which the palette says it fixed |
| `qxzwkv`    | nothing                  | nothing in the list could mean it                |

## Get the code

The example takes the library from its repository, which uses pnpm, so build that first.
In your own project, `npm install ekrina` instead.

```bash
git clone https://github.com/MMMikeM/ekrina.git
cd ekrina && pnpm install --filter ekrina-command-palette... && pnpm build
cd examples/command-palette && pnpm dev
```

## The commands

Each command has a title to search, a category shown beside it, and sometimes keywords, the words someone might type that the title doesn't contain:

## 1. Search the titles

The first palette searches each command's title and lists the best eight:

<Tabs syncKey="framework">
	<TabItem label="Vanilla">
		<Code code={step1} lang="ts" title="src/step-1-search.ts" wrap />
		<CommandPalette step={1} />
	</TabItem>
	<TabItem label="React">
		<Code code={reactStep1} lang="tsx" title="src/react/step-1-search.tsx" wrap />
		<CommandPalette step={1} framework="react" />
	</TabItem>
</Tabs>

`createSearch` builds the searcher once, with the titles as its one field.
It builds the index as soon as the palette exists, so the first keystroke doesn't wait for it.
It passes `limit` because only eight rows are shown, and once eight commands match the query as typed, corrections that couldn't outrank them are never computed.
Results come back best first, so the list is drawn in the order they arrive.
Enter runs the top command and a click runs any of them, and either clears the input.
Type `console` in the palette above and nothing comes back, since no title contains it.

## 2. Search the keywords too

A second field searches the keywords, and the title gets acronyms.
The marked lines are the ones this step adds:

<Tabs syncKey="framework">
	<TabItem label="Vanilla">
		<Code code={step2} lang="ts" title="src/step-2-keywords.ts" ins={addedLines(step1, step2)} wrap />
		<CommandPalette step={2} />
	</TabItem>
	<TabItem label="React">
		<Code code={reactStep2} lang="tsx" title="src/react/step-2-keywords.tsx" ins={addedLines(reactStep1, reactStep2)} wrap />
		<CommandPalette step={2} framework="react" />
	</TabItem>
</Tabs>

With acronyms turned on for the title, `gc` finds Git: Commit and `tt` finds Toggle Terminal.
The keywords are demoted by `SCORES.CONTAINS`, so `dark` finds Preferences: Theme, ranked below any title that contains the query.

Each result's `fields` has one entry per field, in the order the fields were given, and `null` for a field that didn't match.
So `[titleMatch, keywordMatch]` reads them by position.
When only the keywords matched, the row shows them under the title, to make it clear why the command is there.

## 3. Highlight what matched

Each match carries `ranges`, the characters that matched, indexed into the command's own text:

	<TabItem label="Vanilla">

		It sets `textContent` rather than building HTML, so a command title is never parsed as markup.
		<CommandPalette step={3} />
	</TabItem>
	<TabItem label="React">
		<Code code={reactStep3} lang="tsx" title="src/react/step-3-highlight.tsx" ins={addedLines(reactStep2, reactStep3)} wrap />

		<CommandPalette step={3} framework="react" />
	</TabItem>
</Tabs>

## 4. Say when it corrected a typo

This step adds a notice above the list:

<Tabs syncKey="framework">
	<TabItem label="Vanilla">
		<Code code={step4} lang="ts" title="src/step-4-corrections.ts" ins={addedLines(step3, step4)} wrap />
		<CommandPalette step={4} />
	</TabItem>
	<TabItem label="React">
		<Code code={reactStep4} lang="tsx" title="src/react/step-4-corrections.tsx" ins={addedLines(reactStep3, reactStep4)} wrap />
		<CommandPalette step={4} framework="react" />
	</TabItem>
</Tabs>

`bestField` picks the field that set a result's score, the one with the lowest, and `noticeText` reads it from the top result.
It says when that result is a correction, as in Showing results for “terminal”, or that nothing matched.
`corrected` keeps your casing when it fixed a mistyped character, such as two swapped letters, and takes the command's spelling for other corrections, such as a missing letter, so `termnial` shows “terminal” and `comit` shows “Commit”.
The library has corrected typos since the first step, as `termnial` shows in every palette above, and this step only adds the notice.
`noticeText` reads only the top result, so the notice appears when the best match is a correction, even if a fuzzy match sits below it.
The notice is a live region, so a screen reader announces it as it changes.

## 5. Move with the keyboard

This step uses nothing from Ekrina, so skip it if your framework already gives you a combobox.
The input becomes an ARIA combobox, with the list as its listbox:

<Tabs syncKey="framework">
	<TabItem label="Vanilla">
		<Code code={paletteTs} lang="ts" title="src/palette.ts" ins={addedLines(step4, paletteTs)} wrap />
	</TabItem>
	<TabItem label="React">
		<Code code={reactPalette} lang="tsx" title="src/react/palette.tsx" ins={addedLines(reactStep4, reactPalette)} wrap />
	</TabItem>
</Tabs>

In a combobox, focus stays in the input, and `aria-activedescendant` names the row a screen reader should announce as active.
The input has the `combobox` role, the list `listbox` and each row `option`, and `aria-controls` ties the input to the list.
The arrow keys move the active row, wrapping at either end, and Enter now runs the active command rather than the top one.
Escape clears the input without running anything, and a click no longer takes focus from the input.
This is the finished palette at the top of the page.
