Build the palette an editor opens on a shortcut, where you type part of a command, see the best eight and pick one.
Each step below adds one thing to it and runs on the page as it stands after that step.
Every file shown is in [`examples/command-palette`](https://github.com/MMMikeM/ekrina/tree/main/examples/command-palette), and the finished palette is `src/palette.ts`:

<CommandPalette step={5} />

Some queries to try in it:

| Type        | Finds                    | Because                                          |
| ----------- | ------------------------ | ------------------------------------------------ |
| `gc`        | Git: Commit              | the title's initials, with acronyms turned on     |
| `console`   | Toggle Terminal          | a keyword the title doesn't contain              |
| `repl find` | Find and Replace         | every word of the query, in any order            |
| `termnial`  | Toggle Terminal          | a corrected typo, which the palette says it fixed |
| `qxzwkv`    | nothing                  | nothing in the list could mean it                |

## 1. Get the code

The example uses the library from its repository, which uses pnpm, so build that first.
In your own project, `npm install ekrina` instead.

```bash
git clone https://github.com/MMMikeM/ekrina.git
cd ekrina && pnpm install && pnpm build
cd examples/command-palette && pnpm install && pnpm dev
```

It has no framework.
One TypeScript module builds the palette into any element, and Vite serves it.

## 3. Search the titles

The first palette searches each command's title and lists the best eight:

<Code code={step1} lang="ts" title="src/step-1-search.ts" />

`createSearch` builds the searcher once, with the titles as its one field.
It builds the index as soon as the palette exists, so the first keystroke doesn't wait for it.
It passes `limit` because only eight rows are shown, and once eight commands match the query as typed, corrections that couldn't outrank them are never computed.
Results come back best first, so the list is drawn in the order they arrive, and a click runs the command and clears the input.

<CommandPalette step={1} />

Type `console` here and nothing comes back, since no title contains it.

## 4. Search the keywords too

A second field searches the keywords, and the title gets acronyms:

<Code code={lineDiff(step1, step2)} lang="diff" meta='lang="ts"' title="src/step-2-keywords.ts" />

With acronyms turned on for the title, `gc` finds Git: Commit and `tt` finds Toggle Terminal.
The keywords are demoted by `SCORES.CONTAINS`, so `dark` finds Preferences: Theme, ranked level with a title that only contains the query somewhere.

Each result's `fields` has one entry per field, in the order the fields were given, and `null` for a field that didn't match.
So `[titleMatch, keywordMatch]` reads them by position, and when only the keywords matched, the row shows them under the title, to make it clear why the command is there.

<CommandPalette step={2} />

## 5. Highlight what matched

Each match carries `ranges`, the characters that matched, indexed into the command's own text:

<Code code={lineDiff(step2, step3)} lang="diff" meta='lang="ts"' title="src/step-3-highlight.ts" />

`highlighted` turns a field's `ranges` into text and `<mark>` elements.
It sets `textContent` rather than building HTML, so a command title is never parsed as markup.

<CommandPalette step={3} />

## 6. Move with the keyboard

The input becomes an ARIA combobox, with the list as its listbox:

<Code code={lineDiff(step3, step4)} lang="diff" meta='lang="ts"' title="src/step-4-keyboard.ts" />

The input keeps focus, and `aria-activedescendant` points at the active row as the arrow keys move it.
Enter runs the active command, Escape clears the input without running anything, and a click no longer takes focus from the input.

<CommandPalette step={4} />

## 7. Say when it corrected a typo

The last step adds a notice above the list:

<Code code={lineDiff(step4, paletteTs)} lang="diff" meta='lang="ts"' title="src/palette.ts" />

`bestField` picks the field that set a result's score, the one with the lowest, and `noticeText` reads it from the top result.
It says when that result is a correction, "Showing results for “terminal”", or that nothing matched.
A correction always ranks below every match of the query as typed, so the notice only appears when nothing matches the query as typed.
The notice is a live region, so a screen reader announces it as it changes.

The finished palette is the one at the top of this page.
